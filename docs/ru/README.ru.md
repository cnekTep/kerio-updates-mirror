## 📋 Обзор

**Kerio Updates Mirror** — это решение для локального кэширования и зеркалирования обновлений продуктов Kerio Control и
Kerio Connect, которое позволяет:

- Сократить интернет-трафик и ускорить процесс обновления
- Обеспечить обновления для изолированных сетей или систем с ограниченным доступом к интернету
- Автоматически скачивать и обновлять антивирусные базы, базы IPS/IDS Snort и другие компоненты безопасности

## 📊 Функциональные возможности

### Kerio Control

- **Запланированные обновления** - автоматические ежедневные обновления в заданное время:
    - Web Filter (Ключ подсистемы фильтрации контента веб-фильтра)
    - IPS/IDS базы данных
    - Snort шаблоны правил
    - GeoIP базы данных
- **Shield Matrix** - автоматическое обновление сигнатур и черных списков Shield Matrix
- **Антивирусные базы данных** - загружаются автоматически при обращении Kerio Control к зеркалу, с возможностью выбора
  режима обновления:
    - *Прямой режим* - обновления антивируса загружаются напрямую, минуя зеркало
    - *Режим прокси* - обновления передаются через зеркало без локального кэширования
    - *Режим зеркала* - обновления кэшируются зеркалом для быстрого и экономичного повторного доступа

### Kerio Connect

- **Антивирусные базы данных** - загружаются автоматически при обращении Kerio Connect к зеркалу, используя те же режимы
  Прямой / Прокси / Зеркало, что и выше
- **Антиспам-базы данных** - загружаются автоматически при подключении Kerio Connect к зеркалу.:
    - *Режим прокси* - обновления антиспама передаются через зеркало без локального кэширования
    - *Режим зеркала* - обновления антиспама кэшируются зеркалом
- **Проксирование запросов антиспама** - трафик антиспама может направляться через вышестоящий прокси-сервер или VPN.

### Безопасность и контроль доступа

- Аутентификация для веб-интерфейса управления
- Ограничьте доступ к веб-интерфейсу по IP-адресу с поддержкой диапазона CIDR
- Ограничение доступа к обновлениям Kerio по IP-адресу с поддержкой диапазона CIDR

### Сеть

- **Поддержка исходящего прокси** - поддержка HTTP/HTTPS и SOCKS5 прокси для всех исходящих запросов, выполняемых
  зеркалом

## 🚀 Установка и настройка

#### Предварительные требования

- **Docker**
- **Docker Compose версии 2 или более поздней** - Docker Compose версии 1 не поддерживается
  ([инструкция по установке](docker.md))

#### Вариант 1: Запуск из готовых Docker-образов (рекомендуется)

Используются готовые образы, поэтому ничего не компилируется локально - это самый быстрый способ начать работу.

1. [Скачайте Docker-образы](https://t.me/my_store_files_bot?start=kerio-updates-mirror)
2. Загрузите образы из архивов:
   ```bash
    sudo docker load -i kum_nginx_vX.X.X.tar
    sudo docker load -i kum_mirror_vX.X.X.tar
    sudo docker load -i kum_xray_vX.X.X.tar
    sudo docker load -i kum_tor_vX.X.X.tar
   ```
   > Замените "X.X.X" на фактические номера версий из имен файлов загруженных вами архивов.
3. Скачайте или клонируйте репозиторий:
   ```bash
   git clone https://github.com/cnekTep/kerio-updates-mirror.git
   cd kerio-updates-mirror
   ```
4. Запустите контейнеры:
   ```bash
   sudo docker compose up -d
   ```
   > По умолчанию запускается полный стек. Если вам нужны только определенные компоненты, см. варианты модульного
   развертывания ниже.

<details>
<summary><strong>Модульное развертывание</strong></summary>

Зеркало имеет модульную структуру. Вы можете запускать только те компоненты, которые вам нужны, вместо того чтобы
запускать весь стек целиком.

**Mirror** является базовым компонентом. Дополнительные компоненты можно включить, добавив соответствующие Compose
файлы:

* `compose.nginx.yml` - Nginx
* `compose.tor.yml` - Tor
* `compose.xray.yml` - Xray

Некоторые функции доступны только при включении соответствующего компонента:

* **Tor** - `Маршрутизация трафика через сеть Tor`
* **Xray** - `Маршрутизация трафика через локальный Xray`
* **Nginx** - `Ограниченный доступ к веб-интерфейсу по IP` and `Ограниченный доступ к API / обновлениям Kerio по IP`

Если компонент не включен, соответствующие настройки будут недоступны в веб-интерфейсе.

**Только Mirror:**

```bash
sudo docker compose -f compose.mirror.yml up -d
```

**Mirror + Nginx:**

```bash
sudo docker compose \
  -f compose.mirror.yml \
  -f compose.nginx.yml \
  up -d
```

При необходимости можно комбинировать дополнительные компоненты. Например: **Mirror + Nginx + Tor**:

```bash
sudo docker compose \
  -f compose.mirror.yml \
  -f compose.nginx.yml \
  -f compose.tor.yml \
  up -d
```

При сборке образов из исходного кода добавьте к команде параметр `--build`. Например:

```bash
sudo docker compose \
  -f compose.mirror.yml \
  -f compose.nginx.yml \
  up -d --build
```

</details>

#### Вариант 2: Сборка из исходного кода

Создает все образы локально из исходного кода репозитория вместо использования готовых.

1. Скачайте или Клонируйте репозиторий:
   ```bash
   git clone https://github.com/cnekTep/kerio-updates-mirror.git
   cd kerio-updates-mirror
   ```
2. Создайте и запустите контейнеры
   ```bash
   sudo docker compose up -d --build
   ```
   > По умолчанию при этом выполняется сборка и запуск всего стека. Вы также можете выполнить сборку и запустить только
   те компоненты, которые вам нужны, воспользовавшись приведёнными выше параметрами модульного развертывания.

   Например, для сборки и запуска **Mirror + Xray**:

    ```bash
    sudo docker compose \
      -f compose.mirror.yml \
      -f compose.xray.yml \
      up -d --build
    ```

#### Вариант 3: Импорт готовой виртуальной машины

Этот вариант предоставляет полностью настроенное решение "из коробки", идеально подходящее для быстрого развертывания.

1. [Скачайте Виртуальную машину](https://boosty.to/kerio_updates)
2. Импортируйте образ в вашу систему виртуализации (Hyper-V, VMWare - OVF Template)
3. Запустите виртуальную машину

<details>
<summary>📝 Импорт в Hyper-V</summary>

1. Откройте **Диспетчер Hyper-V** (Hyper-V Manager).
2. Выберите **Действие** → **Создать** → **Виртуальная машина**.
3. В мастере создания:
    - укажите имя виртуальной машины (например, **Kerio Updates Mirror**);
    - при необходимости измените расположение файлов;
    - нажмите **Далее**.
4. **Важно:** в разделе выбора поколения укажите **Поколение 1**.
5. Выделите 1024-2048 МБ оперативной памяти.
6. Выберите существующий виртуальный коммутатор.
7. На этапе выбора виртуального диска:
    - выберите **Использовать существующий виртуальный жесткий диск**;
    - укажите скачанный файл `.vhdx`.
8. Нажмите **Готово** и запустите виртуальную машину.

</details>

<details>
<summary>📝 Импорт в VMware</summary>

##### VMware Workstation / Player

1. Запустите VMware Workstation или VMware Player.
2. Выберите **Файл** → **Открыть**.
3. Выберите файл `.ovf` из распакованного архива.
4. Укажите:
    - имя виртуальной машины;
    - расположение файлов (при необходимости).
5. Нажмите **Импорт** и дождитесь завершения процесса.

##### VMware ESXi

1. Откройте веб-интерфейс ESXi или vSphere.
2. Перейдите в раздел **Виртуальные машины**.
3. Нажмите **Создать/Зарегистрировать виртуальную машину**.
4. Выберите **Развернуть виртуальную машину из OVF или OVA файла**.
5. Укажите имя виртуальной машины.
6. Загрузите файлы `.ovf` и `.vmdk`.
7. Выберите хранилище и сеть.
8. Нажмите **Завершить** и дождитесь окончания импорта.

</details>

<details>
<summary>📝 Импорт в Proxmox VE</summary>

1. Загрузите файл резервной копии (`.vma.zst`) на сервер Proxmox по SSH.
2. В веб-интерфейсе Proxmox откройте **Datacenter** → **Storage** → **local**.
3. Перейдите на вкладку **Backups**.
4. Выберите загруженную резервную копию и нажмите **Restore**.
5. При необходимости измените:
    - **VM ID**;
    - имя виртуальной машины;
    - хранилище для виртуальных дисков.
6. Нажмите **Restore** и дождитесь завершения восстановления.
7. Запустите виртуальную машину.

</details>

<details>
<summary>📝 Характеристики и настройка виртуальной машины</summary>

##### Технические характеристики

- **Операционная система**: Debian 12 (минимальная установка)
- **Предустановленное ПО**: SSH, Midnight Commander, htop, ncdu, Docker, Docker Compose,
- **Docker контейнеры**: Portainer, Kerio Updates Mirror

##### Доступ к системе

> ⚠️ **Предупреждение о безопасности**: виртуальная машина поставляется с учетными данными по умолчанию как для
> SSH/root, так и для Portainer.
> Измените **оба** пароля сразу после первого входа в систему - если оставить их без изменений, сервер будет подвержен
> несанкционированному доступу.

- **Учетные данные по умолчанию**:
    - Имя пользователя: `root`
    - Пароль: `root`

##### Начальная настройка

1. Подключитесь к виртуальной машине по SSH (порт 22)
2. ⚠️ **Немедленно смените пароль root**:
   ```bash
   passwd
   ```
3. Настройте корректный часовой пояс:
   ```bash
   dpkg-reconfigure tzdata
   ```
4. Проверьте текущий IP-адрес (по умолчанию используется DHCP):
   ```bash
   ip a
   ```

##### Настройка сети

Для изменения сетевых параметров:

1. Редактирование сетевых интерфейсов:
   ```bash
   nano /etc/network/interfaces
   # или
   mc # затем перейдите к /etc/network/interfaces
   ```
2. Настройка DNS-серверов:
   ```bash
   nano /etc/resolv.conf
   # или
   mc # затем перейдите к /etc/resolv.conf
   ```

##### Управление через Portainer

Виртуальная машина включает предустановленный Portainer для удобного управления Docker-контейнерами:

- **URL**: `https://IP_ВИРТУАЛЬНОЙ_МАШИНЫ:9443`
- **Учетные данные**:
    - Имя пользователя: `admin`
    - Пароль: `admin`

> ⚠️ **Немедленно измените пароль администратора Portainer** после первого входа в систему - учетные данные по
> умолчанию являются общедоступными и не должны оставаться активными.

</details>

## ⚙️ Настройка продуктов Kerio

### Kerio Connect

Для настройки обновлений через локальное зеркало в Kerio Connect необходимо указать промежуточный HTTP-сервер в
настройках:

<details>
<summary>Настройка Kerio Connect (нажмите, чтобы развернуть)</summary>

1. Перейдите в **Конфигурация → Дополнительные параметры → Промежуточный HTTP-сервер**
2. Укажите:
    - **Адрес**: IP_адрес_сервера_с_Docker_контейнерами
    - **Порт**: 8118

</details>

### Kerio Control

Для настройки обновлений через локальное зеркало в Kerio Control необходимо добавить DNS-записи:

<details>
<summary>Настройка Kerio Control (нажмите, чтобы развернуть)</summary>

1. Перейдите в **Конфигурация → DNS → Локальный поиск DNS**
2. Добавьте следующие записи (где IP_сервера_обновлений — это IP-адрес сервера с зеркалом):

| IP-адрес              | Имя хоста                                | Описание                 |
|-----------------------|------------------------------------------|--------------------------|
| IP_сервера_обновлений | kerio-updates-mirror.local               | Kerio Updates Mirror     |
| IP_сервера_обновлений | bda-update.kerio.com                     | Antispam                 |
| IP_сервера_обновлений | bdupdate.kerio.com                       | Antivirus                |
| IP_сервера_обновлений | download.kerio.com                       | IDS/IPS - Snort Template |
| IP_сервера_обновлений | ids-update.kerio.com                     | IDS/IPS/GeoIP            |
| IP_сервера_обновлений | prod-update.kerio.com                    | Distributive Update      |
| IP_сервера_обновлений | register.kerio.com                       | Registration Info        |
| IP_сервера_обновлений | shieldmatrix-updates.gfikeriocontrol.com | ShieldMatrix             |
| IP_сервера_обновлений | wf-activation.kerio.com                  | WebFilter                |

</details>

## 🔧 Расширенные настройки

### Настройка TOR-мостов

TOR-мосты используются для обеспечения доступа к обновлениям даже в случае ограничений доступа:

- Файл конфигурации TOR-мостов: `_tor/bridges/user_bridges.config`
- Система автоматически проверяет доступность интернета через TOR и обновляет мосты при необходимости
- Новые мосты можно получить на [официальном сайте](https://bridges.torproject.org) или
  через [Telegram-бота](https://t.me/GetBridgesBot)

### Мониторинг и управление

- Доступ к веб-интерфейсу управления:
    - `http://IP_СЕРВЕРА/web`
